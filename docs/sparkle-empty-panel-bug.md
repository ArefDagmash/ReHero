# Sparkle Click — Panel Opens but Chat/Delete Button Missing

**Status:** Under investigation  
**Reported:** 2026-07-04  
**Affected:** AI sparkle markers (revisit conversation flow)

---

## 1. Symptom

When the user clicks an AI sparkle marker (the ✨ icon next to highlighted text), the yellow highlight overlay correctly re-appears on the PDF, but the ClarifyPanel opens with **empty content** — neither the conversation text nor the delete button is visible.

> User quote: *"nice it does highlight but I cant see the chat or the delete button"*

---

## 2. Expected vs Actual Behavior

| Step | Expected | Actual |
|------|----------|--------|
| Click sparkle | Panel opens in **single-entry view** showing the saved Q&A | Panel opens but content area is empty |
| Header | Shows mode label + page number + **delete button** | Shows mode label but **no delete button** |
| PDF page | Yellow highlight overlay appears | ✅ Works correctly |

---

## 3. Root Cause Analysis

The panel renders in one of two modes:

```tsx
const isSingleEntryView = !!singleEntry;
```

When `isSingleEntryView` is **false**, the panel falls back to the normal thread/history view. If `thread` is empty (cleared by the early-return effect) and `historyToShow` is empty, the scroll area renders **nothing**.

### 3.1 Why `singleEntry` becomes `null`

```tsx
const singleEntry = useMemo(() => {
    if (!clarifyScrollToEntryId || !savedConversations) return null;
    return savedConversations.find((e) => e.id === clarifyScrollToEntryId) || null;
}, [clarifyScrollToEntryId, savedConversations]);
```

`savedConversations` is derived from:

```tsx
const savedConversations = useAppStore((s) =>
    s.activePaperPath ? (s.conversations[s.activePaperPath] ?? null) : null
);
```

For `singleEntry` to be `null` while a sparkle exists, **one of the following must be true**:

1. `conversations[activePaperPath]` is `undefined` — the conversation was never saved under the current document path.
2. The entry ID stored in the sparkle marker (`m.id`) does **not** match any entry ID in `conversations[activePaperPath]`.
3. `activePaperPath` is somehow falsy when the panel renders (unlikely, because the sparkle would not be visible).

### 3.2 How conversations are saved

In `ClarifyPanel.tsx` → `runStream()`:

```tsx
const s = useAppStore.getState();
const paperPath = s.activePaperPath;
if (paperPath) {
    s.saveConversationEntry(paperPath, {
        id: entryId,          // same ID used for thread & marker
        question: meta.question,
        answer: accumulator,
        sourceHighlight: meta.sourceHighlight,
        mode: sessionModeRef.current,
        page: sessionPageRef.current,
        timestamp: new Date().toISOString(),
    });
    // marker created with the SAME entryId
    s.addAiMarker(`${paperPath}-${sessionPageRef.current}`, {
        id: entryId,
        zoom: s.zoom,
        rects,
        text: meta.sourceHighlight || "",
    });
}
```

Both the conversation and the marker share the same `entryId` (generated by `uid()`). The key is `activePaperPath` at the time the stream finishes.

### 3.3 How the sparkle click restores state

In `Reader.tsx` sparkle `onClick`:

```tsx
useAppStore.setState({
    clarifyPanelOpen: true,
    clarifyScrollToEntryId: m.id,        // marker ID == entry ID
    clarifyHighlightRects: m.rects.map(...),
    clarifyHighlightText: m.text || "",
    clarifyMode: "clarify",
});
```

The panel then looks up `conversations[activePaperPath]` for an entry with `id === m.id`.

### 3.4 Books vs Papers

For **books**, `setActiveBook()` sets `activePaperPath: path` (same as the book's `filePath`). The save and lookup both use `activePaperPath`. In theory the path matches.

For **papers**, the same logic applies via `setActivePaper()`.

**Hypothesis:** There may be a mismatch between the `activePaperPath` captured at save-time vs. the `activePaperPath` at click-time, especially after sidebar navigation or app restart.

---

## 4. Persistent Storage Layer

`conversations` are **not** persisted by Zustand's `persist` middleware (they are excluded from `partialize`). Instead they are manually saved/loaded via `localStorage`:

- **Save key:** `research-reader-conversations`
- **Load location:** `onRehydrateStorage` callback

`aiMarkers` **are** persisted by Zustand. This creates a potential split-brain scenario:

| Data | Persisted by | Storage |
|------|-------------|---------|
| Sparkle markers (`aiMarkers`) | ✅ Zustand `persist` | `localStorage` (key: `research-reader-papers`) |
| Conversation text (`conversations`) | ❌ Manual | `localStorage` (key: `research-reader-conversations`) |

If the manual `localStorage.setItem` in `saveConversations()` fails silently (e.g. quota exceeded), the sparkle survives a reload but the conversation does not. Clicking the sparkle after reload would show an empty panel.

## 6. Recommended Fixes (in priority order)

### 6.1 Add cross-path fallback search

If the entry is not found under `conversations[activePaperPath]`, search all conversation buckets:

```tsx
const singleEntry = useMemo(() => {
    if (!clarifyScrollToEntryId) return null;
    // 1. try current document
    if (savedConversations) {
        const found = savedConversations.find((e) => e.id === clarifyScrollToEntryId);
        if (found) return found;
    }
    // 2. fallback: search every document
    for (const entries of Object.values(allConversations)) {
        const found = entries.find((e) => e.id === clarifyScrollToEntryId);
        if (found) return found;
    }
    return null;
}, [clarifyScrollToEntryId, savedConversations, allConversations]);
```

### 6.2 Add empty-state UI

When `clarifyScrollToEntryId` is set but `singleEntry` is still null, show a message instead of a blank panel:

```tsx
{clarifyScrollToEntryId && !singleEntry && (
    <p className="text-xs text-muted-foreground/50 italic">
        Conversation not found. It may have been deleted or the storage data is missing.
    </p>
)}
```

### 6.3 Audit `saveConversations()` for silent failures

`saveConversations` catches errors but does not surface them to the user:

```ts
function saveConversations(data: Record<string, StoredEntry[]>) {
  try {
    localStorage.setItem("research-reader-conversations", JSON.stringify(data));
  } catch (e) {
    log.store.error("Failed to save conversations to localStorage", e);
  }
}
```

Consider surfacing a toast or in-app warning when `localStorage` write fails, so users know their conversation history may be lost on reload.

### 6.4 Unify storage strategy

Move `conversations` (and `annotations`) into Zustand's `partialize` so they are saved atomically with the rest of the app state, eliminating the split-brain risk.

## 7. Reproduction Steps (to verify)

1. Open any PDF (paper or book).
2. Highlight text → open ClarifyPanel → ask AI a question.
3. Wait for the answer to finish streaming and the ✨ sparkle to appear.
4. Close the panel.
5. Reload the app (or switch sidebar tabs and back).
6. Click the sparkle.
7. Observe: yellow highlight appears, but panel content is empty.

If the panel shows content on step 7 in a fresh session but is empty after reload, the issue is **storage layer split-brain** (fix 6.2 / 6.3 / 6.4).  
If the panel is empty even in a fresh session, the issue is **path mismatch at save time** (fix 6.1).
