## Feature 1: Persistent AI Conversation History

### What it does
Every completed AI response in the ClarifyPanel is saved to `localStorage` (key: `research-reader-conversations`), keyed by paper file path. When you reopen the ClarifyPanel on the same paper, previous sessions appear above a `— new session —` divider with a Bot icon (lucide `Bot`). Each history entry shows the mode, page number, highlighted text, question, and AI answer at 55% opacity so it's visually distinct from the current session. A trash icon in the panel header clears all history for that paper; individual entries can be deleted via an ✕ button that appears on hover.

### Files changed
- `src/types/index.ts` — added `StoredEntry` type (`id`, `question`, `answer`, `sourceHighlight?`, `mode`, `page`, `timestamp`)
- `src/store/useAppStore.ts` — added `conversations: Record<string, StoredEntry[]>` state, `loadConversations`/`saveConversations` helpers, `saveConversationEntry`, `deleteConversationEntry`, `clearConversations` actions; `removePaper` also cleans up conversations; `onRehydrateStorage` loads conversations from localStorage on startup alongside annotations
- `src/components/ClarifyPanel.tsx` — history display UI, save logic in `runStream`, `HistoryEntryBlock` component

### Architecture decisions

**Save location:** Same pattern as annotations — a separate localStorage key (`research-reader-conversations`), loaded manually in `onRehydrateStorage`, NOT in the Zustand `partialize` list (which would put it in `research-reader-papers`).

**Save timing:** The entry is saved directly inside `runStream` the moment `accumulator` is finalized, before any `setThread` state update. This avoids React effect timing issues entirely. `meta` (`{ question, sourceHighlight }`) is passed as an optional third parameter to `runStream` from its two call sites (main panel effect and `handleCustomSend`). `useAppStore.getState()` is used directly inside the async callback to avoid stale closure issues.

**Display:** History is read via a reactive Zustand selector — no local state, no snapshot effect:
```tsx
const savedConversations = useAppStore((s) =>
  s.activePaperPath ? (s.conversations[s.activePaperPath] ?? null) : null
);
```
The fallback is `null`, NOT `[]` — this is critical. `|| []` creates a new array object on every render; Zustand uses `Object.is` equality so it always sees a change → infinite re-render loop. `null === null` is stable. Current thread entry IDs are filtered out so the active session never appears twice in the history list.

### Bugs hit during development

**Crash 1: "can't access lexical declaration 'thread' before initialization"**
Two `useEffect` hooks referencing `thread` were inserted before the `useState<ThreadEntry[]>` declaration. JS temporal dead zone. Fixed by moving effects after all state declarations.

**Bug 2: history not showing after close/reopen**
Original approach used a snapshot `useEffect` + local `historyEntries` state that fired when `clarifyPanelOpen` changed. This was unreliable — snapshot timing vs. the main panel effect that resets thread is nondeterministic when both fire in the same render cycle. Also, the save was in a separate `useEffect` watching `thread`, which had a race condition: when the user closes the panel, `setThread([])` fires, the save effect sees an empty thread, and nothing gets saved. Both were replaced with: reactive selector for display, direct save inside `runStream`.

**Crash 3: "Maximum update depth exceeded"**
The reactive selector had `|| []` as fallback → new array reference on every render → Zustand sees change → re-render → infinite loop. Fixed by returning `null` instead.

## Feature 2: Export Notes as Markdown

### What it does
A new "Export notes (.md)" button in Settings → Data section. Generates a structured Markdown file combining all papers that have annotations or AI conversations. Format: paper title → page-grouped annotation notes with quoted highlights → AI conversations with mode label, page, question, and answer. Downloads as `research-notes.md`, compatible with Obsidian, VS Code, etc. Silent no-op if no content exists.

### Files changed
- `src/components/SettingsPage.tsx` — button added inline next to existing "Export data" button. Reads `{ papers, annotations, conversations }` directly from `useAppStore.getState()` on click (same pattern as existing export button).

## Feature 3: Sparkle Markers on the PDF Page

### What it does
After an AI interaction (simplify / clarify / recap / example / custom), a `✦` sparkle icon (lucide `Sparkles`, indigo color) appears on the PDF page to the right of the highlighted text — persisted across sessions, zoom-aware. It's a purely visual indicator (`pointer-events-none`), not interactive. Markers survive app restarts.

### Files changed
- `src/store/useAppStore.ts` — added `AiMarker` type (`id`, `zoom`, `rects`), `aiMarkers: Record<string, AiMarker[]>` state (in `partialize` so it persists in the main store), `addAiMarker` and `removeAiMarker` actions
- `src/components/ClarifyPanel.tsx` — in `runStream`, right after saving the conversation entry, reads `clarifyHighlightRects` and `zoom` from the store and calls `addAiMarker` with key `${paperPath}-${page}`
- `src/components/Reader.tsx` — added `Sparkles` to lucide import, `aiMarkers`/`removeAiMarker` selectors, updated `showSvg` condition, renders sparkle `<div>` elements positioned at `left: rightX + 6, top: midY - 8` using the same zoom-scaling math as pin markers

### Architecture decisions

**Key format:** `${activePaperPath}-${pageNumber}` — same as `pinnedDoodles`, so the same `pinnedKey` variable in Reader.tsx covers both.

**Positioning:** Right edge of the selection rects (`Math.max(...validRects.map(r => (r.x + r.w) * scale))`), vertically centered on the median rect — mirrors the pin marker midY calculation exactly.

**Zoom-awareness:** Marker stores `zoom` at creation time; Reader scales coordinates by `currentZoom / marker.zoom` on every render, same as pinned doodles.

**Non-interactive:** Made `pointer-events-none` after user feedback — clicking to dismiss was confusing. Markers are permanent visual indicators; the trash button in ClarifyPanel history is the way to clean up.

## Ideas / things left to explore

### Clicking sparkle opens the conversation
Right now sparkles are non-interactive. A natural next step: clicking a sparkle opens the ClarifyPanel and scrolls to or highlights the corresponding history entry. Would require storing the `entryId` in `AiMarker` (it's already there as `id`) and adding logic in ClarifyPanel to scroll to a specific entry on open.

### Mermaid diagram quality for local models (see `docs/mermaid-generation-issues.md`)
Small Ollama models produce syntactically invalid Mermaid (trailing semicolons, LaTeX `$`, unquoted subgraphs, parentheses in diamonds). Cloud models rarely fail. Suggested fix: explicit Mermaid syntax rules in the system prompt + a post-processing pass that strips known bad patterns before rendering. Not implemented yet.

### Annotation ↔ highlight linking
Currently two separate systems: `pinnedDoodles` (visual marks on the page) and `annotations` (per-page text notes). They have no connection. Proposed: add a `noteText` field to `PinnedDoodle` and show inline note editing when clicking a pin marker. Requires changes to `Reader.tsx` and `AnnotationPanel.tsx`.

## Current state of the repo (branch: feature/edge-docking)

Single-page Tauri + React desktop app for reading PDFs with AI assistance. No router — view derived from Zustand store (`activePaperPath ? "reader" : sidebarTab`). LLM streaming supports Ollama, Anthropic, OpenAI, OpenCode via a single `streamLlm()` pipeline in `src/lib/llmStream.ts`. Doodle/coordinate system (Rough.js underlines, zoom-aware pinned doodles) was stabilized before this session.

### Key localStorage keys
- `research-reader-papers` — main Zustand persisted store (papers, settings, pinnedDoodles, aiMarkers, zoom, theme, etc.)
- `research-reader-annotations` — per-paper per-page text notes, loaded manually in `onRehydrateStorage`
- `research-reader-conversations` — per-paper AI conversation history, loaded manually in `onRehydrateStorage`
